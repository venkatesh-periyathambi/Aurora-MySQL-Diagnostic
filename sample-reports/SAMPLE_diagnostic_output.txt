=== DIAGNOSTIC SUMMARY & AURORA-SPECIFIC RECOMMENDATIONS ===
recommendation
Check the following for parallel query contention on Aurora MySQL:
1. GAP/NEXT-KEY locks: check data_locks for wide gap locks blocking parallel DML
2. Isolation level: REPEATABLE-READ creates gap locks; try READ-COMMITTED
3. innodb_autoinc_lock_mode=2 for parallel inserts (interleaved mode)
4. Full table scans: missing indexes cause excess row locks under contention
5. Aurora lock manager memory (Aurora_lockmgr_memory_used): high = many locks held
6. aurora_lock_thread_slot_futex waits: direct signal of row lock contention
7. Aurora redo_log_flush waits: storage layer write latency affecting commits
8. History list length: long-running reads prevent purge, increasing lock footprint
9. Metadata locks: long-running SELECT can block DDL which blocks subsequent DML
10. innodb_deadlock_detect=ON: verify deadlock detection is not disabled
11. innodb_lock_wait_timeout: default 50s; lower it to fail-fast in parallel workloads
12. Check if adaptive hash index causes latch contention (disable with innodb_adaptive_hash_index=OFF)
13. Writer instance only: ensure parallel writes are not hitting a reader (unless write forwarding is configured)
14. Connection count: check if max_connections is being hit causing queuing
